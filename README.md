# Improving Domain-specific NER with Synthetic Data

This repository contains the code and experimental datasets for the master's thesis **Improving Domain-specific NER with Synthetic Data**.

The thesis investigates whether automatically generated training data can improve **named entity recognition (NER)** in scientific publications related to renewable energy, biodiversity, and environmental sustainability.

Using the pretrained `numind/NuNerZero_span` checkpoint within the GLiNER framework, three fine-tuning approaches are investigated:

- **Silver-annotated data** — Fine-tuning using automatically annotated scientific texts.
- **Synthetic data** — Fine-tuning using examples generated by Qwen3-4B-Instruct-2507.
- **Combined data** — Fine-tuning using both silver-annotated and synthetic examples.

The experiments additionally investigate training-data size, few-shot prompting, and annotation guidelines across 16 domain-specific entity categories.

The work was conducted as part of the larger ENGAGE NLP project.

---

## Repository Structure

### `codes/synthetic_data_generation/` — Synthetic Data Generation

- `synthetic_data-base_prompt.py` — Generates synthetic NER examples using baseline prompting without additional annotation guidelines.
- `synthetic_data-guidelines_improved.py` — Generates synthetic NER examples using additional annotation guidelines.

### `codes/data_conversion/` — GLiNER Data Preparation

- `create_gliner_training_data.py` — Converts silver-annotated NER data into GLiNER-compatible training examples.
- `create_gliner_training_data_with_syn.py` — Converts synthetic NER data into GLiNER-compatible training examples.

### `codes/finetuning/` — GLiNER Fine-Tuning

- `finetune_nunerzero_span.py` — Fine-tunes GLiNER using silver-annotated training data.
- `finetune_nunerzero_span_synth.py` — Fine-tunes GLiNER using synthetic data or a combination of silver-annotated and synthetic data.

### `codes/evaluation/` — Model Evaluation

- `evaluate.py` — Evaluates baseline and fine-tuned models using entity-level precision, recall, and F1 score.

## Datasets

### `data/` — Training and Evaluation Data

The thesis uses two datasets containing scientific texts related to renewable energy, biodiversity, and environmental sustainability.

| Dataset | Publications | Sentence-level records | Entity mentions |
|---|---:|---:|---:|
| Silver-annotated | 963 | 262,794 | 287,369 |
| Gold-standard | 125 | 142 | 3,260 |

Both datasets use the same annotation schema containing 16 domain-specific entity categories.

The **silver-annotated dataset** contains automatically generated entity annotations and is used for fine-tuning. The **gold-standard dataset** contains manually verified annotations and is used exclusively for evaluation.

DOI-based deduplication was performed to remove publications occurring in both datasets and prevent publication-level overlap between training and evaluation.

These statistics describe the datasets used in the thesis after deduplication.

### GLiNER Training Format

The annotated datasets are converted into the format required by GLiNER:

```json
{
  "tokenized_text": ["Wind", "turbines", "generate", "electricity", "."],
  "ner": [[0, 1, "wind_energy"]]
}
```

Each entity annotation contains its starting token index, inclusive ending token index, and entity label.

### `synthetic_data/` — Generated Synthetic Datasets

Synthetic training data was generated using `Qwen/Qwen3-4B-Instruct-2507`.

The datasets are organized as follows:

```text
synthetic_data/
├── with_guidelines/
│   ├── synthesized_data_6shot_250_guidelines.json
│   ├── synthesized_data_8shot_250_guidelines.json
│   └── synthesized_data_10shot_250_guidelines.json
└── without_guidelines/
    ├── example_size_experiment/
    │   ├── synthesized_data_8shot_200_base_prompt.json
    │   ├── synthesized_data_8shot_400_base_prompt.json
    │   ├── synthesized_data_8shot_600_base_prompt.json
    │   └── synthesized_data_8shot_800_base_prompt.json
    └── few_shot_experiment/
        ├── synthesized_data_6shot_250_base_prompt.json
        ├── synthesized_data_8shot_250_base_prompt.json
        └── synthesized_data_10shot_250_base_prompt.json
```

The experiments compare:

| Experiment | Few-shot examples | Target examples per entity category |
|---|---|---|
| Baseline vs. guideline prompting | 6, 8, 10 | 250 |
| Synthetic dataset size | 8 | 200, 400, 600, 800 |

The first experiment investigates the effects of annotation guidelines and few-shot prompting. The second examines how synthetic training-data size influences downstream NER performance.

## Quick Start

### 1. Clone the Repository

```bash
git clone https://github.com/<your-username>/<repo-name>.git
cd <repo-name>
```

### 2. Set Up the Environment

```bash
python -m venv .venv
source .venv/bin/activate
```

Install the dependencies required by the scripts and the original ENGAGE NLP framework.

### 3. Start the Qwen Inference Server

Synthetic data generation uses `Qwen/Qwen3-4B-Instruct-2507` through vLLM.

Start the inference server using Apptainer:

```bash
CUDA_VISIBLE_DEVICES=0 apptainer run --nv \
  docker://vllm/vllm-openai:v0.24.0-x86_64-cu129-ubuntu2404 \
  Qwen/Qwen3-4B-Instruct-2507 \
  --host 0.0.0.0 \
  --port 8000 \
  --dtype float16 \
  --gpu-memory-utilization 0.95 \
  --max-model-len 1024 \
  --enforce-eager
```

The server exposes an OpenAI-compatible API on port `8000`. Keep it running while executing the synthetic data generation scripts.

## Running Experiments

Run the following commands from the repository root unless otherwise specified.

### 1. Synthetic Data Generation

Generate synthetic NER examples using baseline prompting:

```bash
python codes/synthetic_data_generation/synthetic_data-base_prompt.py
```

Or generate examples using additional annotation guidelines:

```bash
python codes/synthetic_data_generation/synthetic_data-guidelines_improved.py
```

Configure the number of few-shot examples, generation size, reference dataset, and output paths in the scripts before execution.

### 2. Data Conversion

Convert silver-annotated or synthetic datasets into GLiNER-compatible training data:

```bash
python codes/data_conversion/create_gliner_training_data.py
```

```bash
python codes/data_conversion/create_gliner_training_data_with_syn.py
```

Input and output paths must be configured according to the selected dataset.

### 3. Fine-Tuning With Silver-Annotated Data

Fine-tune the pretrained NuNER Zero-span checkpoint using silver-annotated training examples:

```bash
CUDA_VISIBLE_DEVICES=1 \
python codes/finetuning/finetune_nunerzero_span.py \
  --train_files data/local/ner/gliner_training_data_filtered/data.json \
  --model_name numind/NuNerZero_span \
  -o data/local/ner/models/silver_20 \
  -f \
  --batch_size 3 \
  --accumulation_steps 2 \
  --num_train_epochs 2 \
  --train_fraction 0.2
```

The thesis compares silver-annotated training fractions of 20%, 40%, 60%, 80%, and 100%.

Adjust `--train_fraction` and the output directory for the selected experiment.

### 4. Fine-Tuning With Synthetic Data

For synthetic-only fine-tuning, supply the converted synthetic dataset as the training file:

```bash
CUDA_VISIBLE_DEVICES=1 \
python codes/finetuning/finetune_nunerzero_span_synth.py \
  --train_files data/local/ner/synthesized_data_filtered_ext.json \
  --model_name numind/NuNerZero_span \
  -o data/local/ner/models/synthetic_only \
  -f \
  --batch_size 3 \
  --accumulation_steps 2 \
  --num_train_epochs 2
```

### 5. Fine-Tuning With Combined Data

For combined fine-tuning, provide both the silver-annotated and synthetic training datasets:

```bash
CUDA_VISIBLE_DEVICES=1 \
python codes/finetuning/finetune_nunerzero_span_synth.py \
  --train_files data/local/ner/gliner_training_data_filtered/data.json \
  --synthetic_files data/local/ner/synthesized_data_filtered_ext.json \
  --model_name numind/NuNerZero_span \
  -o data/local/ner/models/with_syn_80 \
  -f \
  --batch_size 3 \
  --accumulation_steps 2 \
  --num_train_epochs 2 \
  --train_fraction 0.8
```

This example uses 80% of the silver-annotated training data together with the synthetic dataset.

The combined experiment reported in the thesis uses a 20% silver-annotated training fraction together with 200 synthetic examples per entity category generated using the eight-shot baseline prompt. To reproduce that configuration, set `--train_fraction 0.2`, select the corresponding synthetic dataset, and use a separate output directory.

The training setup uses two epochs, a per-device batch size of 3, and two gradient accumulation steps, resulting in an effective batch size of 6 on one GPU.

The original experiments were executed as modules within the ENGAGE NLP framework. The commands above use the standalone scripts in this repository and require the corresponding dependencies and data paths.

## Evaluation

The evaluation pipeline computes entity-level **precision, recall, and micro-averaged F1 score** using the gold-standard dataset containing 16 entity categories.

Evaluation requires the original ENGAGE NLP framework and its configuration files. Run the following commands from the original ENGAGE NLP project root.

### Baseline Model

```bash
PYTHONPATH=src CUDA_VISIBLE_DEVICES=1 \
python -m engage_nlp.components.ner.evaluate \
  --config src/engage_nlp/components/ner/configs/evaluation_gliner.yaml \
  --model baseline
```

### Fine-Tuned Model

```bash
PYTHONPATH=src CUDA_VISIBLE_DEVICES=1 \
python -m engage_nlp.components.ner.evaluate \
  --config src/engage_nlp/components/ner/configs/evaluation_gliner.yaml \
  --model /path/to/finetuned_model
```

Replace the model path with the directory containing the fine-tuned checkpoint.

The evaluation pipeline saves predictions and evaluation metrics. The repeated experiments in the thesis report mean overall metrics across five runs.
